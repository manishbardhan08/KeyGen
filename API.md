# Licensing API — Admin Guide

This document explains how to call the KeyGen licensing API from your
software. It is written for the **admin** who owns the product (and the
developer integrating the client), not for end users.

If you only want the quick version, see the *Using Your API Key* panel on your
**Admin → Profile** page. This document is the full reference.

---

## 1. What you need

| Item | Where you get it | Notes |
|------|------------------|-------|
| **API key** | Admin → Profile → **API Key** → *Regenerate Key* | 64-character hex string. Identifies **you** (the admin) to the API. Keep it secret. |
| **License key** | Admin → Keys (generate) or given to a seller | The key your customer activates. Looks like `ADMIN-TAG-XXXXX-XXXXX`. |
| **HWID** | Generated by your client software | A stable, unique machine identifier. See [§7](#7-hwid--device-binding). |

> The API key authenticates **your software as the admin**. Anyone who has it can
> issue licenses as you. If it leaks, click **Regenerate Key** — the old key
> stops working immediately.

---

## 2. Base URL

All endpoints live under:

```
{BASE_URL}/api/v1
```

`{BASE_URL}` is the value configured in `app.baseURL`. Examples used in this
document:

```
Production : https://license.example.com/api/v1
Local dev  : http://localhost:8080/api/v1
```

Three endpoints, all **POST**, all `Content-Type: application/json`:

| Endpoint | Purpose |
|----------|---------|
| `POST /api/v1/auth` | Activate a license key and start a session. Call when the customer logs in / launches. |
| `POST /api/v1/validate` | Re-check a session. Call periodically (e.g. on every launch, or every few minutes while running). |
| `POST /api/v1/logout` | End the session. Call when the customer logs out or closes the app. |

```text
Client software ──► POST /api/v1/auth      (api_key + license_key + hwid)
                        │
                        ▼  returns a session "token"
                  POST /api/v1/validate    (token + hwid)   ← repeat every run
                        │
                        ▼
                  POST /api/v1/logout      (token)
```

---

## 3. Rules the API enforces

These are enforced automatically. Integrate with them in mind:

- **HTTPS is mandatory in production.** A plain `http://` request is rejected
  with `426 Upgrade Required` before any credential is read, so your API key and
  license keys never travel in the clear.
- **Responses are never cached.** Every response carries
  `Cache-Control: no-store` and `Pragma: no-cache`. Do not cache the session
  token to disk in plaintext.
- **Rate limits apply.** Exceeding them returns `429 Too Many Requests` with a
  `Retry-After` header. See [§9](#9-rate-limits).
- **The body must be valid JSON** and under **64 KB** (larger bodies get `413`).
- **One session token ↔ one device.** A token is bound to the `hwid` it was
  issued for; validating it from a different HWID fails with `403`.

## 4. `POST /api/v1/auth` — activate / log in

Use this to activate a license key (first run) and obtain a session token.

### Request

```json
{
  "api_key":     "YOUR_64_CHAR_API_KEY",
  "license_key": "ADMIN-TAG-ABCDE-FGHJK",
  "hwid":        "A-UNIQUE-MACHINE-ID",
  "product":     "MyApp Pro"
}
```

| Field | Type | Required | Description |
|-------|------|:--------:|-------------|
| `api_key` | string | ✅ | Your admin/seller API key. |
| `license_key` | string | ✅ | The customer's license key. |
| `hwid` | string | ✅ | Stable device identifier. |
| `product` | string | ➖ | Your product name. **Strongly recommended** — see [§8](#8-product-name-matching). |

All four are sent as strings. Empty `api_key`, `license_key` or `hwid` is
rejected.

### Success response — `200 OK`

```json
{
  "status":         "ok",
  "token":          "9f8c1e...64 hex chars...2ab",
  "expires_at":     "2026-11-16 14:32:10",
  "duration_hours": 720,
  "duration_days":  30,
  "level":          2,
  "level_name":     "Pro",
  "device_limit":   1,
  "devices_used":   1,
  "hwid":           "A-UNIQUE-MACHINE-ID",
  "activated_at":   "2026-10-17 14:32:10"
}
```

| Field | Meaning |
|-------|---------|
| `token` | **Session token.** Store it in memory / secure storage and send it to `validate`/`logout`. |
| `expires_at` | When the license (and therefore the session) expires. |
| `duration_hours` / `duration_days` | License length. |
| `level` | Numeric feature level (0 = none). |
| `level_name` | Human name your admin defined for that level, or `null`. |
| `device_limit` | Max devices this key may activate on. |
| `devices_used` | Devices currently bound to the key. |
| `hwid` | Echoed back for verification. |
| `activated_at` | Timestamp of first activation (unchanged on later logins). |

### Error responses

Errors use this shape (HTTP status equals the `status` field):

```json
{
  "status": 403,
  "error": 403,
  "messages": { "error": "Invalid license key." }
}
```

| HTTP | Message | Meaning |
|:----:|---------|---------|
| `400` | `Malformed request body.` / `Missing parameters.` | Body not JSON, or a required field missing/empty. |
| `401` | `Invalid API key.` | The `api_key` is unknown. |
| `403` | `Reseller account is banned.` | The account owning the API key is banned. |
| `403` | `Reseller account expired.` | The account owning the API key has expired. |
| `403` | `Invalid license key.` | Key not found, banned, or belongs to another admin's scope. |
| `403` | `Product mismatch.` | `product` does not match the key/account product. |
| `403` | `License expired.` | Key was already activated and its time is up. |
| `403` | `This license is already active on its maximum number of devices.` | `device_limit` reached and this HWID is not one of the bound devices. |
| `503` | *(offline)* | The admin's software kill-switch is **off** — see [§10](#10-software-kill-switch-503). |

### Behaviour notes

- **First activation** starts the clock: `expires_at = now + duration_hours`, the
  key is marked `used`, and the HWID is bound.
- **Unactivated keys never expire** — the clock only starts on first activation.
- **Later logins** from an already-bound device succeed. From a new device they
  succeed only while `devices_used < device_limit`.
- An **expired key can never bind a new device**.

## 5. `POST /api/v1/validate` — check a session

Call this on each subsequent run (or periodically while the app is open) to
confirm the session is still valid and to read the current level.

### Request

```json
{
  "token": "9f8c1e...64 hex chars...2ab",
  "hwid":  "A-UNIQUE-MACHINE-ID"
}
```

| Field | Type | Required | Description |
|-------|------|:--------:|-------------|
| `token` | string | ✅ | The token returned by `auth`. |
| `hwid` | string | ✅ | The **same** HWID used at `auth` time. |

### Success response — `200 OK`

```json
{
  "status":     "ok",
  "expires_at": "2026-11-16 14:32:10",
  "level":      2,
  "level_name": "Pro"
}
```

### Error responses

| HTTP | Message | Meaning |
|:----:|---------|---------|
| `400` | `Malformed request body.` / `Missing parameters.` | Body not JSON, or `token`/`hwid` missing. |
| `401` | `Invalid token.` / `Session invalid.` | Token unknown, or its owner was deleted/changed role. |
| `403` | `HWID mismatch.` | The `hwid` does not match the one the token was issued for. |
| `403` | `Session expired.` / `Account expired.` / `Account is banned.` | Token, owner account, or ban state invalid. |
| `403` | `License no longer valid.` | The underlying license key is missing or banned. |
| `503` | *(offline)* | Software kill-switch is off. |

> **Trust only `200 OK`.** Treat any non-200 as "deny access / ask to log in
> again".

---

## 6. `POST /api/v1/logout` — end a session

Best-effort cleanup. Safe to call even if the token is already gone.

### Request

```json
{ "token": "9f8c1e...64 hex chars...2ab" }
```

### Response

```json
{ "status": "ok" }
```

This always returns `200` once a `token` field is present, even if the token was
unknown (idempotent). A missing/empty token returns `400 Missing token.`

## 7. HWID — device binding

**HWID** = "hardware ID": a string that identifies the machine, so one license
can be limited to N devices.

Rules for a good HWID:

- **Stable** — the same machine must produce the same value across restarts,
  reboots and app updates.
- **Unique** — different machines must produce different values.
- **Opaque/short-ish** — any string works; a hash is fine (e.g. 32–64 hex chars).
- **Do not** use values that change (current IP, random UUID generated per run,
  a value based on the Windows volume serial that can change).

Simple, reliable ideas:

- Windows: the `MachineGuid` at
  `HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`.
- Linux: `/etc/machine-id`.
- Cross-platform shortcut: a hash of `(OS + CPU model + main disk serial + MAC)`.

Example (Python):

```python
import hashlib, platform, uuid

def make_hwid() -> str:
    raw = f"{platform.system()}|{platform.machine()}|{uuid.getnode()}"
    return hashlib.sha256(raw.encode()).hexdigest()
```

Send the **same** HWID to `auth` and to every `validate` call.

## 8. Product name matching

`product` prevents a key issued for one app being used in another.

The rule (case-insensitive, whitespace-trimmed):

- If the **license key** and/or the **account** declares a product name, then the
  `product` you send **must equal it**. Otherwise → `403 Product mismatch.`
- If neither the key nor the account declares a product, the check is skipped.

**Always send `product`** in `auth`. If you omit it while the key/account has a
product set, the request is rejected. Set your product name once in
**Admin → Profile → Product**.

## 9. Rate limits

Two independent token buckets, per 60-second window:

| Scope | Limit | Applies to |
|-------|------:|-----------|
| Per client IP | **60 requests / 60s** | All three endpoints. |
| Per credential | **30 requests / 60s** | Each distinct `api_key`, `license_key`, or `token`. |

Exceeded → `429 Too Many Requests`:

```json
{ "status": "error", "message": "Too many requests. Please slow down and try again shortly." }
```

Header: `Retry-After: <seconds>` (between 60 and 600). **Honour it** — wait that
long before retrying, with exponential backoff for repeated 429s.

Practical cadence: `validate` on app start and then every few minutes is fine.
Do **not** poll every few seconds.

---

## 10. Software kill-switch (`503`)

As an admin you can switch your software **off** from
**Admin → Profile → Software Access**. When off, all clients in your scope
receive:

```json
{ "status": "offline", "message": "Server off, kindly wait." }
```

with HTTP `503` and a `Retry-After: 300` header. You control the `message`
text. Live sessions are affected too, so flipping the switch blocks running
clients on their next `validate`.

Recommended client behaviour: show the `message` to the user and retry later;
do **not** treat it as "license invalid".

> Note the offline body uses `status` + `message` (not the `messages.error`
> shape). Branch on the HTTP code first.

---

## 11. Recommended client flow

```text
On app start:
  1. If no stored token:
       POST /auth  { api_key, license_key, hwid, product }
       - 200  → save token in memory, allow use, start validate timer
       - other → show messages.error, deny
  2. If a stored token exists:
       POST /validate { token, hwid }
       - 200  → allow, refresh level/expiry
       - 401/403 → discard token, ask for license key again
       - 503  → show offline message, retry later
       - 429  → back off per Retry-After

Every few minutes while running:
  POST /validate { token, hwid }   → same handling as above

On logout / exit:
  POST /logout { token }           → then discard the token
```

Always branch on the **HTTP status code**, then read `messages.error` (or
`message` for offline) for the reason.

## 12. Code examples

### cURL

```bash
# 1) Authenticate
curl -sS -X POST https://license.example.com/api/v1/auth \
  -H 'Content-Type: application/json' \
  -d '{
        "api_key":     "YOUR_64_CHAR_API_KEY",
        "license_key": "ADMIN-TAG-ABCDE-FGHJK",
        "hwid":        "A-UNIQUE-MACHINE-ID",
        "product":     "MyApp Pro"
      }'

# 2) Validate
curl -sS -X POST https://license.example.com/api/v1/validate \
  -H 'Content-Type: application/json' \
  -d '{ "token": "TOKEN_FROM_STEP_1", "hwid": "A-UNIQUE-MACHINE-ID" }'

# 3) Logout
curl -sS -X POST https://license.example.com/api/v1/logout \
  -H 'Content-Type: application/json' \
  -d '{ "token": "TOKEN_FROM_STEP_1" }'
```

### PHP

```php
function apiCall(string $path, array $payload): array {
    $ch = curl_init('https://license.example.com/api/v1/' . $path);
    curl_setopt_array($ch, [
        CURLOPT_POST           => true,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER     => ['Content-Type: application/json'],
        CURLOPT_POSTFIELDS     => json_encode($payload),
        CURLOPT_TIMEOUT        => 15,
    ]);
    $body   = curl_exec($ch);
    $status = curl_getinfo($ch, CURLINFO_HTTP_CODE);
    curl_close($ch);

    return [$status, json_decode((string) $body, true)];
}

[$code, $res] = apiCall('auth', [
    'api_key'     => 'YOUR_64_CHAR_API_KEY',
    'license_key' => 'ADMIN-TAG-ABCDE-FGHJK',
    'hwid'        => make_hwid(),
    'product'     => 'MyApp Pro',
]);

if ($code === 200) {
    $token = $res['token'];            // keep in memory
    // ... allow the app ...
} else {
    echo $res['messages']['error'] ?? 'Login failed';
}
```

### Python (requests)

```python
import requests

BASE = "https://license.example.com/api/v1"

def auth(api_key, license_key, hwid, product):
    r = requests.post(f"{BASE}/auth", json={
        "api_key": api_key,
        "license_key": license_key,
        "hwid": hwid,
        "product": product,
    }, timeout=15)

    if r.status_code == 200:
        return r.json()["token"]
    if r.status_code == 503:
        raise RuntimeError(r.json()["message"])          # offline
    raise PermissionError(r.json()["messages"]["error"])  # denied

def validate(token, hwid):
    r = requests.post(f"{BASE}/validate",
                      json={"token": token, "hwid": hwid}, timeout=15)
    return r.status_code == 200, r.json()

def logout(token):
    requests.post(f"{BASE}/logout", json={"token": token}, timeout=15)
```

### C# (.NET)

```csharp
using System.Net.Http;
using System.Net.Http.Json;

static async Task<string?> AuthAsync(HttpClient http, string apiKey,
                                     string licenseKey, string hwid, string product)
{
    var res = await http.PostAsJsonAsync("https://license.example.com/api/v1/auth",
        new { api_key = apiKey, license_key = licenseKey, hwid, product });

    if (res.StatusCode == System.Net.HttpStatusCode.OK)
    {
        var data = await res.Content.ReadFromJsonAsync<Dictionary<string, object>>();
        return data?["token"]?.ToString();
    }
    // 401/403 → deny, 429 → back off, 503 → offline
    throw new Exception(await res.Content.ReadAsStringAsync());
}
```

### Node.js

```js
async function auth(apiKey, licenseKey, hwid, product) {
  const res = await fetch('https://license.example.com/api/v1/auth', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ api_key: apiKey, license_key: licenseKey, hwid, product }),
  });
  const data = await res.json();
  if (res.status === 200) return data.token;
  if (res.status === 503) throw new Error(data.message);
  throw new Error(data.messages?.error ?? 'Login failed');
}
```

## 13. Testing locally

With `php spark serve` (see `app.baseURL`):

```bash
curl -sS -X POST http://localhost:8080/api/v1/auth \
  -H 'Content-Type: application/json' \
  -d '{"api_key":"...","license_key":"...","hwid":"test-1","product":"MyApp Pro"}'
```

Notes:

- In `development`, HTTPS is **not** required (the `426` rule only runs in
  `production`), so `http://` works locally.
- In `development`, JSON responses are pretty-printed; in `production` they are
  compact.
- Use a real API key from **Admin → Profile** and a real license key from
  **Admin → Keys**.

## 14. Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `401 Invalid API key.` | Wrong/rotated API key | Copy the current key from Admin → Profile. |
| `403 Invalid license key.` | Key typo, banned, or from another admin's scope | Check the key in Admin → Keys. |
| `403 Product mismatch.` | `product` sent ≠ key/account product | Send the exact product name, or clear it in Profile. |
| `403 ... maximum number of devices.` | New device, limit reached | Raise `device_limit`, or reset HWID for that key (Admin → Keys → Reset HWID). |
| `403 License expired.` | Time is up | Issue/extend a key. |
| `403 HWID mismatch.` | `validate` sent a different `hwid` than `auth` | Send the identical HWID. |
| `426 HTTPS is required...` | Called over plain HTTP in production | Use `https://`. |
| `429 ...` | Rate limit hit | Wait `Retry-After` seconds; slow the polling. |
| `503 { "status": "offline" }` | Kill-switch off | Turn software back on in Admin → Profile. |
| `413 Request body too large.` | Body > 64 KB | Send only the small JSON payload. |

## 15. Quick reference

| Method | Path | Body | Success |
|--------|------|------|---------|
| POST | `/api/v1/auth` | `api_key, license_key, hwid, product` | `200 {status:"ok", token, expires_at, ...}` |
| POST | `/api/v1/validate` | `token, hwid` | `200 {status:"ok", expires_at, level, level_name}` |
| POST | `/api/v1/logout` | `token` | `200 {status:"ok"}` |

**Status codes:** `200` success · `400` bad request · `401` bad credential ·
`403` denied/expired/banned/devices · `413` body too large · `426` HTTPS required ·
`429` rate limited · `503` software offline.

**Error body:** `{ "status": <code>, "error": <code>, "messages": { "error": "..." } }`
(except `503`, which is `{ "status": "offline", "message": "..." }`).
