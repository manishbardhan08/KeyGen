# KeyGen

A CodeIgniter 4 license-key management console. It issues, distributes and
validates software license keys with **HWID (device) binding**, and exposes a
small JSON API that client software calls on every run.

```
Owner ──creates──► Admin ──creates──► Seller
                     │                  │
                     └──── keys ────────┘   (sellers buy from the admin's plans)
                              ▲
     client software ────► /api/v1/{auth,validate,logout}
```

Both **Admin** and **Seller** accounts carry an API key — the API accepts either,
so an admin can license their own software or resell through sellers.

## Roles

| Role | Can do |
|------|--------|
| **Owner** | Create / delete admins and reset their passwords; change own password. No keys, plans or pricing. |
| **Admin** | The vendor. Manage sellers (create / edit / recharge / extend / ban / delete); define license **levels** (including admin-only ones) and **key plans**; generate, extend, ban, reset-HWID, delete and export keys; set the product name and a software on/off switch; hold their own API key. |
| **Seller** | Reseller. Buy keys from the creating admin's plans (the seller's balance is debited); may act only within the per-key permissions the admin grants (`extend`, `ban`, `reset HWID`, `delete`) and only for the levels the admin lets them sell. |

## Features

- **Device binding** — a key activates on 1..100 distinct HWIDs (`Devices per key`);
  the bound HWID list is stored per key.
- **Admin-defined levels** — admin A's "Level 1" is independent of admin B's, and a
  level can be marked admin-only (hidden from sellers).
- **Per-admin key plans** — sellers only see/buy the durations and levels their admin
  priced and allowed (`sell levels`).
- **Product matching** — the API rejects a license whose configured product name does
  not match the client's, whenever either side declares one.
- **Software kill-switch** — an admin can take their software offline; live sessions
  receive `503` + a custom message.
- **Licensing API** (`POST /api/v1/{auth,validate,logout}`) — SHA-256-hashed session
  tokens, no key/owner enumeration, per-IP *and* per-credential rate limits,
  HTTPS-only in production.
- **Panel** — CSV export, dark/light theme, 30-minute idle auto-logout with a
  "still there?" warning, and "remember me".
- **Branded error pages** — `400` / `403` / `404` / `429` / `500` render a
  self-contained, light-and-dark KeyGen page (`app/Views/errors/html/`) that needs
  no assets or database to display.

## Security

- CSRF on every panel write (API excepted); all destructive routes are **POST-only**.
- **Strict CSP** — `script-src` has no `'unsafe-inline'`; inline scripts run only via a
  per-response nonce and inline `on*=` handlers have been removed.
- **Rate limits** — login (per IP + username), the public API (per IP *and* per
  credential), and every signed-in panel write (per user + per IP).
- **Secrets** — API keys stored as HMAC-SHA256 (queryable) plus an encrypted display
  copy; API session tokens stored as SHA-256; passwords bcrypt-hashed (min 8 chars).
- HTTPS forced (non-API) with HSTS; the API **rejects** cleartext with `426` instead of
  redirecting, so credentials never travel in the clear.
- In production sessions are IP-bound; sign-out destroys the session and clears the
  remember cookie.
- **Error responses never leak internals** — the raw exception message/stack is
  shown only when `CI_ENVIRONMENT ≠ production`; production visitors get the branded
  page above.

Full checklist: [DEPLOYMENT.md](DEPLOYMENT.md) §12 / §13.

> **Behind a reverse proxy / CDN:** set `app.proxyIPs` in `.env` so IP rate-limits and
> the "is it HTTPS?" check see the real client, not the proxy.

## Setup

```bash
composer install
cp .env.production.example .env       # then edit it (see below)
php spark key:generate                 # writes encryption.key into .env
php spark migrate
php spark db:seed OwnerSeeder          # creates the first owner
php spark serve                        # http://localhost:8080
```

Minimum `.env` values:

| Key | Value |
|-----|-------|
| `CI_ENVIRONMENT` | `development` or `production` |
| `app.baseURL` | your URL, with trailing slash |
| `database.default.*` | DB connection |
| `encryption.key` | generated by `php spark key:generate` |

The owner login comes from `OWNER_NAME` / `OWNER_USERNAME` / `OWNER_PASSWORD` in
`.env`. In **production** the seeder refuses to run without a real password:

```bash
OWNER_PASSWORD='a-strong-password' php spark db:seed OwnerSeeder
```

The seeder is idempotent — re-running it with an existing username just skips.

## Encryption-key rotation

`encryption.key` decrypts the stored API-key **display** copies
(`users.api_key_display`). The API itself authenticates against the SHA-256 hash, so
licensing keeps working even without the display copy. To rotate the key without
losing those copies:

```bash
php spark keygen:reencrypt        # re-encrypts the copies and prints the new encryption.key line
```

It re-encrypts in place and prints the new line for you to paste into `.env` — it
never edits `.env` itself, so the change stays auditable.

## API

```
POST /api/v1/auth      { api_key, license_key, hwid, product }
POST /api/v1/validate  { token, hwid }
POST /api/v1/logout    { token }
```

All responses are `Cache-Control: no-store`. In production, plain-HTTP calls are
rejected with `426 Upgrade Required` so credentials never travel in the clear, and an
admin's software kill-switch answers with `503`.

Full request/response reference, error codes, rate limits and client examples (cURL,
PHP, Python, C#, Node.js): see [API.md](API.md). Admins can also read the same reference
in-app at **Admin → Developer → API Docs** (`/admin/docs`).
